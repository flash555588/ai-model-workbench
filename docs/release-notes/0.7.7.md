# AI Model Workbench 0.7.7

`0.7.7` expands 3D format support, makes the format and conversion pipeline
runtime-extensible, improves cross-platform converter discovery, and fixes
renderer resource leaks, performance hot paths, privacy, and inline preview UX.

## New Formats

- Added OFF (`off`) and Gmsh (`msh`) mesh sources via the local Python/trimesh
  conversion bridge.
- Added Parasolid (`x_t`, `x_b`) and CATIA (`catpart`, `catproduct`) sources via
  the FreeCADCmd native-import bridge, generalizing the existing SolidWorks
  (`sldprt`) converter.

## Extensibility

- The format registry is now runtime-extensible: `registerFormatCapability`,
  `unregisterFormatCapability`, `resetFormatCapabilities`, and
  `getFormatCapabilities` let custom formats be added (or built-ins overridden)
  without editing the built-in list. `directLoader` accepts arbitrary loader
  identifiers.
- Direct-format loading now dispatches through the registry
  (`getDirectLoaderKind`: `gltf`/`obj`/`stl`/`ply`) in both renderers instead of
  duplicated per-extension switches.
- `createConversionManager` accepts `extraConverters` so custom converters can be
  registered at runtime alongside the opt-in built-ins.

## Cross-Platform

- Added Linux FreeCAD AppImage discovery (scanning `~/Applications` and
  `~/Downloads` for `FreeCAD*.AppImage`) and a `freecad` console-binary fallback
  for FreeCADCmd-based CAD converters. Settings and environment overrides remain
  highest priority.

## Fixes

- Babylon helper materials (ground, grid, axis, bounding box) are now disposed
  with their meshes, stopping a per-toggle GPU/material leak.
- Three.js `BoxHelper` geometry and material are disposed on
  selection/focus/bounding-box/measurement-target changes.
- The Babylon `OBJFileLoader._loadMTL` override is restored in `finally`, so a
  failed OBJ load no longer leaks a stale closure onto the shared prototype.
- Babylon `destroy()` guards scene/engine disposal in `finally`, so a controller
  throw cannot strand the WebGL context.
- The remote draft no longer sends the vault path, user notes, user tags,
  annotation labels, or heading references when geometry sharing is disabled;
  the model path is reduced to its basename.
- Three.js OBJ material warnings preserve the underlying read/parse error.
- `readHeadingSection` narrows its catch to the vault read so genuine failures
  are logged instead of masquerading as empty sections.
- The heading-pin observer clears its scan timer when the mutation observer
  stops.
- The Babylon network guard now refuses `ftp:` URLs, matching the Three.js guard.

## Performance

- The Babylon Slice overlay line systems are pooled and updated in place per
  drag frame instead of being disposed and reallocated.
- The Babylon measurement hover raycast is coalesced to one per animation frame.
- Three.js Slice drag reuses scratch `Vector3` buffers instead of allocating per
  pointer event.
- Hand-synced renderer tuning constants moved to a shared `preview/tuning.ts`.

## Inline Preview UX

- One-time "drag to rotate · scroll to zoom · right-drag to pan" hint on inline
  `3d` previews.
- Floating filename + format badge on inline `3d` and `3dgrid` previews, hidden
  during active interaction, with the full vault path as its tooltip.
- `grab`/`grabbing` cursors on preview canvases.
- Loading overlay marked with `role="status"`/`aria-live` and `aria-busy`, plus a
  keyboard focus ring on the tabbable canvas.
- Smooth interaction-mode highlight transition on the preview host.

## Maintainability

- Deduplicated the registered-part rank function and part field normalizers into
  `utils/registered-part-persistence.ts`, and base64 data-URL decoding into
  `utils/base64.ts`.

## Behavior

- Babylon.js compatibility mode remains the default single-model route.
- Three.js opt-in routing, Converted GLB fast-path behavior, and Babylon fallback
  remain unchanged.
- No settings or persisted-data migration is introduced.
