# AI Model Workbench 0.9.0

`0.9.0` fixes advertised direct-format routing and conversion preferences while
keeping Babylon.js compatibility mode as the default. Minimum Obsidian: `1.5.0`.

## Stability fixes

- Enabled Three.js routes now reach the bundled 3MF, DAE, OFF, PCD, and XYZ loaders
  in inline previews, Live Preview, and direct file view.
- Explicit OBJ conversion preferences are respected. Registered desktop FBX
  conversion remains preferred; mobile and unregistered-converter Three routes
  load FBX directly. Converter execution failures remain visible.
- PCD/XYZ explain which renderer settings are required before creating a preview.
- Babylon fallback is attempted only for formats its direct loaders implement,
  preserving the original Three-only loader error.
- Diagnostics use the enabled format registry and implemented loader kinds.
- OFF rejects invalid counts, truncated geometry, and invalid vertex references;
  polygon faces are triangulated while preserving their original winding.
- Older Obsidian releases retain the settings `display()` entry point.

## Local resources

Direct 3MF/DAE/FBX loaders accept embedded textures only. External texture references
cannot trigger requests; convert these models to an embedded GLB for textured
previews. CAD conversion, remote drafting consent, `3dgrid`, and conservative
workbench behavior keep their existing boundaries.

## Regression coverage

New tests cover routing, registry overrides, converter priority, mobile execution,
localized point-cloud feedback, and embedded-resource guards. Synthetic
3MF/DAE/OFF/PCD/XYZ fixtures exercise real browser loading and direct-edit routes.

Release checks:

Install `main.js`, `manifest.json`, and `styles.css` from the verified build.
