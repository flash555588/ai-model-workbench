# AI Model Workbench 0.6.0+ 更新日志

`0.6.0+` 是 AI Model Workbench 从“能预览 3D 模型”走向“可验证的模型工作台”的版本线。它的核心方向是：提升 Three.js 单模型查看质量，保留 Babylon.js 作为 `3dgrid`、保守 workbench、兼容回退和未来 SPLAT 能力路径。

这不是一次全面替换 Babylon.js 的版本线。`GLB/GLTF/STL/PLY/OBJ` 的直读预览默认强化 Three.js，复杂网格、转换兜底和高风险路径继续保持稳健分工。

## 版本概览

| 版本 | 状态 | 重点 |
|------|------|------|
| `0.6.0` | 已发布 | Three.js 能力树、视觉质量、测量、知识工作流、诊断和验证门禁 |
| `0.6.1` | 已发布 | Obsidian 源码审核修复，保留 `0.6.0` 行为不变 |
| `0.6.0+` current main | 未发布补充 | PLY 点云证据链、极小模型真实尺度、小零件聚合、格式血缘保留、文档拆分 |

## 0.6.0 主要更新

### Three.js 展示质量

- `GLB/GLTF/STL/PLY/OBJ` 单模型路径默认使用 Three.js。
- 新增 Three.js capability profile 和 quality snapshot，用于诊断当前 route 的格式能力、颜色管线、几何统计、相机精度、小零件信息和帧预算。
- `GLB/GLTF` 保留 glTF PBR 材质语义，避免全局材质重写导致颜色失真。
- `STL/PLY` 支持顶点色路径，存在颜色属性时启用对应材质能力。
- `OBJ/MTL` 只给 diffuse/base color 纹理设置 sRGB，normal、roughness 等非颜色贴图保持线性空间。
- PLY 点云大小会根据模型包围盒自适应，减少小模型点过大、大模型点不可见的问题。

### 色彩、精度和小零件

- Three.js 默认保持 `SRGBColorSpace` 和 `NoToneMapping` 作为颜色基线。
- 相机 fit 使用真实包围盒尺度，不再用一单位 floor 隐性放大小模型。
- `near/far`、控制器距离、拾取阈值和测量标记根据模型尺度调整。
- 新增颜色基准和小零件 fixture，覆盖色块偏色、小螺丝/针脚/薄片可见性、选中和测量。

### 流畅性和性能

- Three.js 记录 frame budget、慢帧、平均帧耗时、p95、最大帧耗时、DPR 调整和 idle skip。
- 交互时先降低像素比以保证旋转、缩放、拖拽手感，静止后恢复质量。
- 预览静止时渲染循环休眠，只在交互、动画、观察器或需要重绘时唤醒。
- Babylon.js 预览离开视口时暂停渲染，`3dgrid` 跳过未变化 cell，减少无效工作。

### 测量和标注

- 标尺支持单位校准、三轴 delta、完成记录保留、清除和 Markdown 导出。
- 已完成测量在退出测量模式后仍然可见，未完成端点会干净取消。
- Three.js 和 Babylon.js 共用测量格式，预览工具栏只显示当前 route 真正支持的能力。
- 标注遮挡、标签避让和移动中的刷新批处理得到强化。

### 知识笔记和零件证据

- 知识生成保持 local-first：生成报告、JSON sidecar、知识索引、预览证据、标注引用和零件草稿。
- 生成状态现在明确记录 pending、failed、success，部分写入失败会留下可诊断状态。
- 远程草稿仍为可选功能，只发送清洗后的证据，不上传原始模型。
- 命名 GLB/GLTF group 作为更高置信度零件候选，未命名 mesh 仍可作为普通候选。
- 直接文件视图会自动注册捕获到的零件候选，用于后续模型的复用识别。

### 转换、诊断和发布

- 转换超时从 120 秒提高到 300 秒，减少大 STEP 模型误超时。
- 转换管理器增加外层超时，避免卡死预览。
- 新转换产物默认写入 `.obsidian/ai-model-workbench/converted-assets`，也可通过“辅助文件夹”设置改到指定库文件夹；同时继续复用比源文件更新的旧 `.ai3d-converted.*` 旁路产物，降低目录噪声和陈旧几何风险。
- 诊断报告展示渲染 route、转换状态、知识生成状态和 Three/Babylon 能力差距，同时默认隐藏本地路径和敏感配置。
- 发布验证覆盖 build、release asset 版本、体积、hash、预览、诊断、知识索引和 Obsidian 实机 smoke test。

## 0.6.1 主要更新

`0.6.1` 是源码审核修复版，不改变 `0.6.0` 的渲染、测量、转换、诊断和知识工作流行为。

- 远程草稿 timeout helper 改用标准 `window.setTimeout()` / `window.clearTimeout()`。
- 转换 timeout helper 和预览验证脚本同步避开旧的 timer 写法。
- 保留 `0.6.0` 的 Three.js 能力树和所有 release gate。

## 当前 main 的未发布补充

这些内容属于 `0.6.0+` 继续推进的增量，可作为下一个 `0.6.x` 版本的候选更新：

- PLY 点云已进入 Three.js summary、part evidence、picking、measurement、material audit 和 disposal 路径，不再用假的三角面数量描述点云。
- 极小模型的正交相机、阴影和 grid helper 使用真实 bounds，不再被一单位下限放大。
- 泛化的小碎片会合并为低置信度 detail cluster，既保留小零件线索，也避免把导入噪声切得过细。
- 零件拆分会保留格式血缘，包括源格式、渲染格式和 direct/convert 策略，例如 `STEP -> GLB (convert)`。
- README 冗余内容已收敛，详细使用指南和常见语法拆分到独立文档。

## 没有改变的边界

- Babylon.js 没有被移除。
- `3dgrid` 仍走 Babylon.js 能力路径。
- broader workbench 不在 `0.6.0+` 中默认迁移到 Three.js。
- SPLAT 和更复杂的转换链仍保留在 Babylon.js 或保守兜底路径。
- 不新增远程模型处理，不上传原始模型资产。
- 移动端继续支持直读格式和预览，但本地 CAD/FBX/3MF/DAE 转换仍是桌面能力。


## 短版发布文案

`0.6.0+` 强化了 AI Model Workbench 的 Three.js 单模型查看主链：GLB/GLTF/STL/PLY/OBJ 获得更可靠的颜色、材质、点云、小零件、相机精度和流畅性诊断；测量、标注、知识笔记、转换缓存和发布验证也同步加固。Babylon.js 继续承担 `3dgrid`、保守 workbench 和兼容兜底，确保项目在提升展示质量的同时保持稳定。
