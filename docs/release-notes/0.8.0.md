# AI Model Workbench 0.8.0

`0.8.0` is a precision-measurement and reliability release for the Obsidian
3D preview, conversion, knowledge, and release workflows.

## Measurement

- Short-distance measurement now targets the current selected object by
  default and snaps endpoints to transformed mesh vertices and triangle edges.
- When no object is selected, the first measurement click locks the target for
  the session. Holding `Alt`/`Option` keeps free surface picking available as a
  backup.
- Babylon.js and Three.js now share renderer-neutral measurement sessions,
  endpoint pairing, marker reuse, overlay lifecycle, snap-input caching, and
  geometry indexing. Native marker, line, and label drawing remains behind
  backend adapters.
- Hover previews, target focus, cancellation, calibration refresh, and cleanup
  now follow the same state transitions in both renderers.

## Preview And Formats

- The inline Slice inspector now exposes explicit Move and Rotate controls for
  the cutting-board gizmo.
- Three.js can directly load 3MF, COLLADA (DAE), OFF, PCD, and XYZ when that
  renderer route is selected.
- FBX falls back to the Three.js direct loader when FBX2glTF is unavailable,
  while converted loading remains preferred when the converter exists.
- Three.js detects Draco-compressed GLB/GLTF content before loading and reports
  an actionable compatibility message.
- Native browser hover tooltips were removed from preview controls while
  accessible names remain available to assistive technology.

## Reliability And Privacy

- Remote drafting now requires HTTPS for public endpoints. Plain HTTP is
  limited to real loopback hosts, and vault paths, notes, tags, and note
  references are removed independently of geometry-sharing consent.
- Persisted settings, conversion cache records, and agent task plans are
  validated before entering runtime state.
- Timed-out conversion callers no longer break in-flight job deduplication.
- Knowledge indexes are committed only after their report and sidecar files
  have been written successfully.
- Obsidian 1.13 settings-search integration is available through the
  declarative settings API, with the existing imperative UI retained for older
  Obsidian versions.

## Engineering

- Pull requests now run lint, typecheck, unit, settings, remote-draft,
  knowledge-index, diagnostics, build, and release-asset verification.
- Release builds use the exact dependency lockfile and run the expanded check
  matrix before publishing.
- The `obsidian` API typings are updated to 1.13.1 and type-aware unsafe-value
  lint rules are enabled.

## Compatibility

- Babylon.js compatibility mode remains the default single-model renderer.
  Three.js remains an explicit rollout and converted-GLB fast path.
- STEP/STP support remains conversion-only and desktop-only. CadQuery/OCP and
  trimesh must be configured locally; mobile cannot run STEP conversion.
- The minimum supported Obsidian version remains `1.5.0`.
