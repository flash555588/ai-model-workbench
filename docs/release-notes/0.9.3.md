# AI Model Workbench 0.9.3

`0.9.3` improves the direct file-view knowledge workflow and tool discoverability.
It includes the 0.9.0–0.9.2 reliability fixes. Minimum Obsidian: `1.5.0`.

## Tools and information hierarchy

- Focus, disassembly, measurement, and annotation have visible short labels.
- Active modes keep a short next-action hint visible, with accessible live status.
- Knowledge actions precede model statistics. The initial primary action generates
  a knowledge note; the saved index becomes the primary action after success.
- Summary metrics use a compact grid and localized performance labels. Backend
  and raw route reasons remain available under collapsed renderer diagnostics.
- Draft provenance is explained: local evidence and templates produce drafts,
  while part candidates still need review.

## Generation feedback and consistency

Live progress covers evidence capture, output ownership checks, local analysis,
part drafts, optional remote drafting, report writes, and index writes. Failures
show a reason and a retry action beside the model; previously saved notes remain
available. Progress is runtime-only, so stale pending records after restart do
not disable retry.

File-view actions bind the clicked model path, summary, evidence, and screenshot
before lazy loading the generation module. Another active leaf cannot redirect
the report to a different model. Progress observers cannot interrupt writes, and
older phase/finish notifications cannot clear a newer run. Success clears live
progress before the optional report-opening step.

## Narrow leaves and touch controls

Leaves at or below 640 CSS px stack the model viewport above the sidebar based
on their container width, including narrow splits inside a wide desktop window.
Wider leaves retain the resizable sidebar. Mobile tool hit areas have minimum
width and height of 40 CSS px.

## Verification

Validation covers 400 unit tests in 57 files, TypeScript, lint, settings migration,
knowledge indexes, 35 browser preview scenarios, production release assets, and
Obsidian 1.13.7 integration on Windows (2026-10-02). Real Obsidian checks exercise generation progress, an
injected write failure followed by retry, and 360/480/768 px leaf layouts.
Native touch-device usability and external CAD installations remain outside the
local Windows verification scope.

The local installation ZIP contains only `main.js`, `manifest.json`, and
`styles.css`; its extracted contents match the verified files by SHA-256.
Install these three assets together. This local preparation does not publish
the release to GitHub.
